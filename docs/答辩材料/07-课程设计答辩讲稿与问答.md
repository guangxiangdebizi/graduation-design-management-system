# 课程设计答辩讲稿与问答

## 1. 一句话介绍

> 本项目是一个基于 JSP、Servlet、JDBC 和 MySQL 的毕业设计全流程管理系统，面向
> 管理员、教师和学生三类角色，实现课题发布、学生选题、教师审批、阶段文档提交与评阅、
> 答辩安排、成绩统计和消息通知。

## 2. 8～10 分钟答辩讲稿

### 第 1 分钟：项目背景

毕业设计管理涉及学生、指导教师和管理员三类人员。传统线下管理存在信息分散、选题状态不透明、
文档版本难追踪、答辩安排和成绩统计效率低等问题。

因此本项目的目标是建立一套统一系统，将：

```text
用户管理
→ 教师发布课题
→ 学生申请
→ 教师审批
→ 开题/中期/终稿
→ 答辩
→ 成绩和统计
```

串成完整流程。

### 第 2 分钟：角色和功能

管理员：

- 管理用户和公告
- 安排答辩
- 批量导入答辩 Excel
- 查看统计并导出成绩
- 查看消息和操作日志

教师：

- 发布和维护课题
- 审批学生选题
- 查看指导学生
- 审核开题、中期和终稿
- 查看答辩安排

学生：

- 浏览和筛选课题
- 提交申请
- 查看审批结果
- 提交三阶段文档
- 查看反馈、成绩和答辩

### 第 3 分钟：技术架构

本项目采用课程中的传统 JavaWeb MVC：

```text
JSP 表示层
Servlet 控制层
JavaBean 数据对象
DAO 数据访问层
SQLHelper / Druid
MySQL
```

所有请求先经过 AuthFilter，再进入 Controller。Controller 调用 DAO，把查询结果放到 request，
然后 forward 到 JSP。写操作完成后 redirect，采用 Post/Redirect/Get 防止重复提交。

前端使用 JSP、HTML、CSS、原生 JavaScript、Bootstrap 和 ECharts。项目不是完全前后端分离，
而是服务端渲染；统计页面通过 fetch 调用 JSON 接口。

### 第 4 分钟：数据库设计

数据库共 9 张表：

```text
users
topics
topic_selections
documents
document_versions
announcements
defense_schedules
messages
operation_logs
```

核心关系：

- 教师用户一对多发布课题。
- 学生和课题通过选题申请关联。
- 学生按课题提交文档。
- 当前文档一对多关联历史版本。
- 学生一对一关联答辩安排。

数据库不仅存数据，还通过唯一约束实现：

- 用户名和学号唯一
- 一名学生最多一个有效选题
- 每名学生每阶段一条当前文档
- 每个学生一条答辩安排
- 分数限制 0～100

### 第 5 分钟：核心流程

以选题为例：

1. 教师发布课题并设置名额。
2. 学生浏览开放课题并提交申请。
3. 教师审批。
4. 审批通过后课题已选人数加一。
5. 达到上限后课题自动关闭。

系统在后端和数据库两层保证“一人一题”和“不能超额”。

### 第 6 分钟：事务和并发

选题审批不是简单改一个状态，它还要更新课题人数和开放状态。如果这些 SQL 分开提交，中间失败会导致
申请已通过但人数没增加。

所以使用 JDBC 事务：

```java
conn.setAutoCommit(false);
conn.commit();
conn.rollback();
```

同时用 `SELECT ... FOR UPDATE` 锁定学生和课题，防止两个并发请求同时拿到最后一个名额。

这是项目比普通 CRUD 更有业务深度的部分。

### 第 7 分钟：文档状态机和文件

文档顺序是：

```text
选题通过
→ 开题报告通过
→ 中期检查通过
→ 终稿通过
→ 答辩资格
```

文档状态包括 submitted、reviewed 和 rejected。只有 rejected 可以重新提交，重新提交前旧内容进入
版本表。上传使用 Servlet `Part` 和 `@MultipartConfig`，限制 10MB 并使用扩展名白名单和 UUID 文件名。

文件不能直接通过 `/uploads/` 访问，必须经过 DownloadController 按角色鉴权。

### 第 8 分钟：权限和安全

AuthFilter 统一完成：

- Session 登录校验
- 三角色路径权限
- 账号停用和角色变化检查
- CSRF 校验
- UTF-8
- 安全响应头

密码使用 BCrypt，新密码不以明文保存；同时兼容初始化数据中的旧 MD5。页面输出使用 EscapeUtil 做
HTML 转义，数据库使用 PreparedStatement。

### 第 9 分钟：特色与总结

项目特色：

- 三角色业务闭环
- 选题并发控制
- 文档状态机和版本历史
- Excel 导入导出
- AJAX + ECharts
- 操作日志和自动通知
- 数据库唯一约束与事务

项目完整覆盖了课程中的 JSP、Servlet、Session、Filter、JavaBean、DAO、JDBC、MySQL 和文件上传，
并在此基础上增加了业务一致性和安全设计。

## 5. 高频答辩问题

### Q1：为什么选择 JSP + Servlet，而不是 Spring Boot？

课程重点是 JSP、Servlet、JDBC 和 MVC。本项目需要展示 request、response、Session、Filter、
Servlet 生命周期和 JDBC 等底层知识。使用 Spring Boot 会隐藏这些过程，所以选择传统 JavaWeb，
更贴合课程要求。

### Q2：系统前后端分离吗？

不是完全分离。系统是一个 WAR，JSP 在服务器端渲染 HTML。逻辑上仍有前端和后端分层：
JSP/CSS/JS 是表示层，Servlet/DAO/JDBC 是后端。统计模块通过 AJAX 调用 JSON 接口。

### Q3：MVC 分别是什么？

- Model：JavaBean 和 DAO。
- View：JSP。
- Controller：Servlet。

Filter 位于 Controller 前，负责统一权限和安全检查。

### Q4：为什么 JSP 不直接访问数据库？

直接访问会使页面和 SQL 耦合，难维护、难复用。项目核心页面由 Servlet 查询 DAO，再通过 request
传给 JSP，页面只负责展示。

### Q5：forward 和 redirect 有什么区别？

forward 是服务器内部转发，只有一次请求，可以保留 request 属性，适合查询后进入 JSP。
redirect 是浏览器重新请求，地址栏变化，适合写操作后防止重复提交。

### Q6：为什么使用 Session？

HTTP 本身无状态。登录成功后将 User 放入 Session，后续请求用 Session 确认身份和角色。

### Q7：Filter 有什么作用？

统一处理每个请求都需要的逻辑：编码、登录、角色、CSRF、安全响应头，避免在每个 Servlet 重复编写。

### Q8：如何防止 SQL 注入？

DAO 使用 PreparedStatement 和 `?` 参数，不直接拼接用户输入。

### Q9：为什么使用 Druid？

DriverManager 每次创建物理连接成本较高。Druid 复用连接，并提供连接有效性检测，但 DAO 仍使用标准 JDBC。

### Q10：为什么要事务？

选题审批和文档版本更新包含多条 SQL，必须全部成功或全部失败。事务保证原子性。

### Q11：如何避免课题超额？

审批事务中锁定课题行，检查 `selected_count < max_students`，成功后人数加一，达到上限自动关闭。

### Q12：如何保证一名学生只能选一个题？

后端事务检查，加数据库生成列 `active_guard` 和唯一索引双重保证。

### Q13：为什么 topics 中保存 selected_count？

它是为了快速显示和判断名额的冗余字段。项目使用事务确保它与 approved 申请数量一致。

### Q14：文档为什么需要版本表？

被退回后重新提交时需要保留旧内容，便于追踪修改过程。当前表保存最新版本，版本表保存历史。

### Q15：如何保证文档顺序？

提交中期前查询开题是否 reviewed，提交终稿前查询中期是否 reviewed。答辩前要求终稿 reviewed。

### Q16：前端的 min/max 能保证分数吗？

不能，用户可以构造请求。Controller 和数据库 CHECK 都再次限制 0～100。

### Q17：如何防止越权下载？

Filter 禁止直接访问 uploads，DownloadController 根据当前用户角色及文档归属判断权限，再输出文件流。

### Q18：密码如何保存？

新增或修改密码使用 BCrypt；为了兼容旧初始化数据，验证时仍支持旧 MD5。Session 中的 User 会清空密码字段。

### Q19：CSRF 是什么，系统如何处理？

CSRF 是利用已登录浏览器伪造请求。系统为 Session 生成 Token，前端给 POST 表单加入 Token，Filter 比对。

### Q20：XSS 如何处理？

JSP 输出用户数据前使用 EscapeUtil 将 `<`、`>`、引号等字符转义，避免被浏览器作为脚本执行。

### Q21：为什么数据库使用外键？

保证引用完整性，例如文档引用的学生和课题必须存在。

### Q22：为何三类账号放在一张 users 表？

登录、消息、公告、日志都能统一关联用户；课程项目规模下比三张账号表更简洁。

### Q23：项目有哪些索引？

主键、用户名、学号，以及有效选题、学生文档类型、文档版本号和答辩学生的唯一索引。

### Q24：Excel 如何实现？

使用 Apache POI。导入通过 WorkbookFactory 读取单元格，导出通过 XSSFWorkbook 创建工作簿。

### Q25：ECharts 数据从哪里来？

statistics.jsp 使用 fetch 请求 AdminStatsController，Controller 调用 StatsDao 聚合 MySQL 数据并返回 JSON。

### Q26：当前架构的不足是什么？

- 部分辅助 JSP 仍直接访问 DAO。
- 没有独立 Service 层。
- Scriptlet 较多。
- Tomcat Maven Plugin 较旧。
- 自动化测试覆盖不足。

### Q27：下一版本如何改进？

1. 增加 SelectionService、DocumentService、DefenseService。
2. 使用 JSTL/EL 进一步纯化 JSP。
3. 使用 Flyway 管理数据库版本。
4. 文件保存到 Web 根目录之外。
5. 增加并发和 Controller 集成测试。
6. 升级 Tomcat 9。

## 6. 老师可能追问的设计取舍

### 为什么没有全面加 Service 层？

为了与课程 Controller + DAO 结构保持一致，同时控制课程设计规模。当前复杂事务封装在 DAO 中，
后续业务扩大时再提取 Service。

### 为什么不用 MyBatis？

课程重点是 JDBC。手写 DAO 可以展示 PreparedStatement、ResultSet 和连接管理。

### 为什么不用 JWT？

系统是同一服务器上的传统 Web 应用，Session 更简单且符合课程内容。JWT 更适合跨端或分布式 API。

### 为什么不是微服务？

业务规模和课程目标不需要。单体 WAR 部署简单，事务和页面开发更直观。

## 7. 演示故障预案

如果现场数据库未启动：

```text
先启动 MySQL80 服务
确认 jdbc.properties 用户名和密码
```

如果端口占用：

```text
检查 8086
修改 pom.xml 中 Tomcat port
```

如果页面空白或 500：

```text
检查 Tomcat 日志
检查数据库表是否执行 init.sql 或迁移脚本
```

如果 CDN 无网络：

```text
Bootstrap/ECharts 可能加载失败
后续版本可将依赖下载到 WebContent 本地
```
