# 选题后阶段提交与三教师答辩评分流程

> 目标：把“学生选上课题之后”的流程固定为可实现、可答辩、不过度复杂的版本。任务书不强制系统化，重点补齐阶段材料提交、指导教师审核、系主任指定答辩教师、三教师独立评分和平均分。

---

## 1. 核心结论

选题成功后，系统主线应是：

```text
学生获得最终课题
  -> 学生提交开题报告
  -> 指导教师审核开题
  -> 学生提交中期检查
  -> 指导教师审核中期
  -> 学生提交终稿/结题材料
  -> 指导教师审核终稿并给出过程/论文成绩
  -> 系主任为该学生指定三名本专业答辩教师
  -> 三名答辩教师分别录入答辩成绩
  -> 系统计算三人成绩平均值作为答辩成绩
  -> 答辩均分达到 60 分及以上则视为通过
  -> 学生查看终稿成绩、答辩成绩和综合结果
```

本项目不强制增加“任务书”模块。任务书在真实教学中经常通过微信、QQ、线下沟通等方式下达，系统可以不作为强约束。

---

## 2. 当前实现状态

当前系统已有：

- 选题最终结果：`topic_assignments`。
- 阶段材料：`documents`，包含 `proposal`、`midterm`、`final`。
- 阶段顺序控制：开题通过后才能提交中期，中期通过后才能提交终稿。
- 指导教师审核文档：通过或退回；终稿可填写分数。
- 旧答辩安排：`defense_schedules`，目前包含时间、地点、分组、一个答辩分数字段。

当前不符合真实业务的点：

| 环节 | 当前系统 | 目标流程 |
|---|---|---|
| 答辩安排责任人 | 管理员安排 | 系主任/专业负责人安排 |
| 答辩安排内容 | 时间、地点、分组、单个分数 | 只指定三名本专业答辩教师 |
| 答辩评分 | 一个 `defense_schedules.score` | 三名教师分别评分 |
| 答辩成绩 | 单字段保存 | `AVG(三名教师分数)` |
| 最终成绩展示 | 终稿成绩为最终成绩，答辩不参与 | 显示终稿成绩、答辩平均分，可选计算综合成绩 |

---

## 3. 阶段材料流程

### 3.1 阶段顺序

```text
proposal 开题报告
  -> reviewed 后
midterm 中期检查
  -> reviewed 后
final 终稿/结题材料
```

### 3.2 学生提交条件

学生提交阶段材料必须满足：

- 已有最终课题，即存在 `topic_assignments` 或旧流程 `topic_selections.status='approved'`。
- 当前材料上传开关已开启。
- 当前阶段前置阶段已通过：
  - 开题无前置。
  - 中期要求开题 `reviewed`。
  - 终稿要求中期 `reviewed`。
- 同一阶段材料如果已通过或待审核，不允许重复提交。
- 被退回的材料允许重新提交，并保存历史版本。

### 3.3 指导教师审核

指导教师只能审核自己课题学生提交的材料。

审核规则：

| 材料类型 | 教师操作 | 是否计入成绩 |
|---|---|---|
| 开题报告 | 通过 / 退回 | 不计成绩 |
| 中期检查 | 通过 / 退回 | 不计成绩 |
| 终稿/结题材料 | 通过 / 退回 / 填写终稿成绩 | 作为终稿成绩 |

终稿成绩可以理解为“指导教师对论文/设计成果的评价”，不等同于答辩成绩。

---

## 4. 答辩流程目标

本项目采用简化但真实的答辩流程：

```text
终稿通过
  -> 系主任指定三名本专业教师
  -> 三名教师各自打分
  -> 系统平均
```

不做：

- 答辩时间。
- 答辩地点。
- 详细分组管理。
- 答辩秘书、组长权限。
- 复杂权重配置。

这些内容真实存在，但对当前课程项目会增加大量页面和数据维护成本，不适合作为当前重点。

---

## 5. 答辩数据模型

保留 `defense_schedules` 作为“某学生是否进入答辩安排”的主记录，但职责改为：

```text
一名学生的一次答辩安排记录
```

新增两张表：

### 5.1 `defense_committee_members`

记录系主任给某个学生指定的三名答辩教师。

```text
id
schedule_id
teacher_id
member_order
created_at
```

约束：

- 同一 `schedule_id` 最多三名教师。
- 同一 `schedule_id + teacher_id` 不能重复。
- 教师必须是本专业教师或本专业系主任兼教师身份。

### 5.2 `defense_scores`

记录每名答辩教师的评分。

```text
id
schedule_id
teacher_id
score
comment
score_time
```

约束：

- `score` 在 0 到 100 之间。
- 只有该 `schedule_id` 的答辩委员才能评分。
- 同一教师对同一学生只能保留一条评分，重复提交为更新。

## 6. 角色职责

| 角色 | 职责 |
|---|---|
| 学生 | 提交开题、中期、终稿；查看答辩教师和平均答辩分 |
| 指导教师 | 审核自己指导学生的阶段材料；如果被系主任指定为答辩教师，则录入答辩分 |
| 系主任/专业负责人 | 查看本专业材料进度；对终稿已通过学生指定三名本专业答辩教师 |
| 管理员 | 维护账号、系统开关、模板、统计；不负责具体答辩教师安排 |

## 7. 答辩评分规则

### 7.1 可安排答辩条件

系主任只能给满足以下条件的学生安排答辩教师：

- 学生属于当前系主任的学院和专业。
- 学生已有最终课题。
- 终稿/结题材料 `final` 已审核通过。

### 7.2 答辩教师范围

可选答辩教师必须满足：

- `users.role IN ('teacher','director')`
- `users.status=1`
- `users.college = 当前系主任college`
- `users.major = 当前系主任major`

是否允许指导教师参与自己学生答辩，可以作为规则配置。当前简化实现建议允许，因为课程项目数据量有限；如果老师要求严格回避，再加“不允许选择该学生指导教师”校验。

### 7.3 平均分

答辩成绩计算：

```text
答辩成绩 = 三名教师已提交分数的平均值
```

展示规则：

- 0 人评分：待评定。
- 1-2 人评分：显示“已评分 x/3，暂存平均分”。
- 3 人评分：显示“答辩成绩 xx.xx 分”。
- 3 人均分达到 60 分及以上：答辩通过，可以结课。
- 3 人均分低于 60 分：答辩未通过，不能结课。

如果必须严格等三人全部评分才出分，页面可以只在 `score_count=3` 时显示最终答辩分。

## 8. 最终成绩建议

当前系统最终成绩等于终稿成绩：

```text
final_score = documents(doc_type='final').score
```

改造后建议页面展示两个核心成绩：

```text
终稿成绩：指导教师审核终稿时填写
答辩成绩：三名答辩教师平均分
```

综合成绩可以先不强行加入数据库，只在页面上按规则计算：

```text
综合成绩 = 终稿成绩 * 0.6 + 答辩成绩 * 0.4
```

如果不想引入权重争议，答辩时可以表述为：

> 系统分别管理终稿成绩和答辩成绩；当前展示综合参考分，权重可按学院要求调整。

## 9. 页面改造

### 9.1 系主任端

新增或改造：

```text
/director/defense.action
```

功能：

- 列出本专业终稿已通过学生。
- 展示该学生当前三名答辩教师。
- 提供三个教师下拉框。
- 保存后生成/更新 `defense_schedules` 和 `defense_committee_members`。
- 不录入时间、地点、分组。

### 9.2 教师端

改造：

```text
/teacher/defense.action
```

功能：

- 展示“我需要参与评分的学生”。
- 显示学生、课题、指导教师、当前评分状态、平均分。
- 教师录入自己的分数和评语。

### 9.3 学生端

改造：

```text
/student/defense.action
```

功能：

- 显示三名答辩教师。
- 显示评分进度。
- 显示答辩平均分。

### 9.4 学生成绩页

改造：

```text
/student/grades.action
```

展示：

- 终稿成绩。
- 答辩平均分。
- 综合参考分。

## 10. 验收场景

| 编号 | 场景 | 预期 |
|---|---|---|
| D1 | 终稿未通过学生 | 系主任不能安排答辩教师 |
| D2 | 系主任给本专业学生选择三名本专业教师 | 保存成功 |
| D3 | 系主任选择重复教师 | 保存失败 |
| D4 | 系主任选择跨专业教师 | 保存失败 |
| T1 | 被指定教师进入教师端答辩页 | 能看到待评分学生 |
| T2 | 未被指定教师访问 | 看不到该学生 |
| T3 | 三名教师分别打分 | 生成三条 `defense_scores` |
| T4 | 教师重复提交分数 | 更新自己的评分 |
| S1 | 学生查看答辩 | 能看到三名教师和平均分 |
| S2 | 只有两名教师打分 | 显示评分进度 2/3 |
| S3 | 三名教师打完 | 显示最终答辩平均分 |

## 11. 答辩表述建议

```text
学生选题完成后，系统进入阶段材料管理流程。学生依次提交开题报告、
中期检查和终稿/结题材料，每一阶段均由对应指导教师审核，且后续阶段
依赖前一阶段通过。终稿通过后，学生获得答辩资格。

答辩部分由系主任按本专业范围指定三名答辩教师。三名教师分别登录系统
对学生进行评分，系统自动计算三人成绩平均值作为该学生答辩成绩。
三名教师评分完成后，答辩均分达到 60 分及以上视为通过，低于 60 分视为未通过。
这样既避免了单一教师评分带来的偏差，也符合实际教学中答辩小组集体评价的流程。
```
